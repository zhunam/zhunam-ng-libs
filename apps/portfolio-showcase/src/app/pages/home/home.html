FAQ

What's in this portfolio? +

Two kinds of work. Applications: complete products like Luan Patterns, deployed on their own, plus live demos like the Crypto Market Dashboard. And libraries: five independent Angular packages published on npm, Data Grid, Form Builder, Auth, PDF Generator, and Calendar. New pieces of either kind show up as cards above once they're finished.

Is the code open source? +

Depends on the piece. Every library ships under the MIT license, free for any use, and some may add optional paid Pro tiers for advanced features later, with no fixed timeline yet. The demos hosted on this site, the Crypto Market Dashboard included, live in the same public repository as the libraries. Standalone products like Luan Patterns are closed source: you can use them live, but their code isn't published.

Do the applications use the libraries? +

The Crypto Market Dashboard does: its market table is @zhunam/data-grid, the currency converter is @zhunam/form-builder, and its PDF export is @zhunam/pdf-generator, imported only through each package's public entry point, the same API an external project gets. That's the point of it: proving the libraries hold up against real, live data, not just their own demo pages.

Is the data in the demos real? +

The library demos use sample data, so every feature can be tried without an account or an API key. The Crypto Market Dashboard fetches live market data from the CoinGecko public API on every visit. Luan Patterns works on your own images, processed entirely in your browser: nothing is uploaded to a server.

What Angular versions are supported? +

Every library targets the same range, ^20.0.0 || ^21.0.0 || ^22.0.0, reviewed each time Angular ships a new major and verified with real production builds at both ends of it. The applications aren't constrained by that floor and run on recent Angular versions.

Why build libraries instead of using something like Angular Material? +

Complete design systems are excellent, but they require adopting their entire visual language and CDK just to obtain a single component. Each library here focuses on a single problem, has no dependencies on CSS frameworks, and is small in size. They don't replace a complete design system when you really need one, but rather serve as an alternative when you don't.
